# AI connection (manual model configuration) — normative spec

> **Partly superseded by [EMBEDDING_SETTINGS_SPEC.md](EMBEDDING_SETTINGS_SPEC.md)** (migration `20261026090000_embedding_dimensions`). The form now has a fourth, optional input — *Embedding dimensions* — and the "vectors must be 1536-dimensional" rule below is gone: any size from 8 to 4096 is accepted if the provider is *measured* to produce it. Where this file says `expectedDimension`, `1536`, `reembedRequired` or `documentsAffected`, the newer spec wins (`dimensionLimits`, `embeddingChange`, `reindex`).

Replaces the multi-provider / per-task settings UI with **one connection form of exactly three text inputs** — *API key*, *Chat / LLM model ID*, *Embedding model ID* — on top of the existing credential + preference tables (no competing config system). Migration `20261024090000_ai_connection_embedding_identity` (additive: `Document.embeddingDimension`, `ModelPreference.validatedAt`, `ModelPreference.embeddingDimension`; backfills the 1536 already stored). Earlier contracts still apply (PART3–5, `rag_agent/CONTRACT.md`).

## 0. Principles
1. **No hard-coded models, no allow-list.** Model ids are free text (format-validated only). A model is "supported" only because the provider *actually answered* a minimal call with it.
2. **Validate before activating.** A new/changed configuration is saved only if the provider accepts the key, the chat model and the embedding model (and the embedding has the dimension this installation can store). A failed attempt changes nothing: the previous working configuration stays active (single transaction, nothing written on failure).
3. **Provider is derived, never typed.** Fixed server-side endpoints per provider (no user-supplied URLs → no SSRF). Derivation from the key: `sk-or-` → OpenRouter (**default for anything unrecognised**), `gsk_` → Groq (chat only → embedding check fails clearly), `AIza` → Gemini (Google AI Studio; case-sensitive), other `sk-` → OpenAI, `mock-…` → the test-only mock provider **only when `ALLOW_MOCK_PROVIDER` is enabled** (never in production; there is no silent fallback to mock). The form shows the detected provider read-only ("OpenRouter — detected from your key"); it is not an input.
4. **Embedding identity = provider + model + dimension.** Equal dimension does not imply the same vector space. Documents are searchable only when their recorded identity equals the current configuration; otherwise they are *stale*, excluded with a clear message (never silently mixed), and can be re-embedded.
5. Keys: server-side only, AES-256-GCM at rest (existing `ProviderCredential`), masked everywhere (`••••abcd`), never in responses/logs/errors/URLs/browser storage; empty key input never overwrites the saved key.

## 1. rag_agent — `POST /v1/providers/validate` (bearer-protected, JSON)
Request `{ provider, api_key (SecretStr), chat_model (1–200), embedding_model (1–200) }` (provider must be a registered one; mock only when enabled). Always HTTP 200 for a processed request (422 for invalid shape, 401 without token):
```jsonc
{ "ok": false, "provider": "openrouter", "embedding_dimension": 3072 | null,
  "checks": {
    "auth":      { "ok": true,  "latency_ms": 180 },
    "chat":      { "ok": false, "code": "MODEL_NOT_FOUND", "message": "safe text" },
    "embedding": { "ok": false, "code": "EMBEDDING_DIMENSION_MISMATCH", "message": "This model returned 3072-dimensional vectors when asked for 1024, so it does not support that size. …", "dimension": 3072 } } }  // (historic example; see EMBEDDING_SETTINGS_SPEC §3)
```
`ok` = all three checks ok. A check that did not run (because auth failed) is `{ "ok": null, "skipped": true }`. Order: **auth** (authenticated call; OpenRouter `GET /key`), then **chat** (one non-streaming completion, `max_output_tokens` ≤ 8, temperature 0, prompt "Reply with OK."; model must answer — any non-empty text or a valid empty-finish response counts; HTTP/provider error codes are normalised), then **embedding** (one request, input `"StudyForge connection test"`, sends `dimensions=1536` where the adapter already does so for OpenAI-family ids): the response must contain exactly one vector of finite floats (no NaN/inf, non-empty); its **actual length is returned as `dimension`** and compared with `EMBEDDING_DIMENSIONS` (1536): different ⇒ `EMBEDDING_DIMENSION_MISMATCH` with the measured number in the message. Providers without embeddings ⇒ `CAPABILITY_UNSUPPORTED`. Error codes are the existing normalised set (`PROVIDER_AUTH_INVALID`, `PROVIDER_RATE_LIMITED`, `PROVIDER_TIMEOUT`, `PROVIDER_UNAVAILABLE`, `MODEL_NOT_FOUND`, `QUOTA_EXCEEDED` (credits), `CONTENT_FILTERED`, `PROVIDER_ERROR`, malformed response ⇒ `PROVIDER_ERROR`); messages are fixed safe text — never upstream bodies, never the key. Each check has its own timeout (≤ 20 s), no retries beyond the adapter's bounded ones. Secrets are bound for redaction for the whole call. The mock provider implements it deterministically (key `mock-valid-key`; chat models `mock-chat*`; embedding `mock-embed`; others ⇒ `MODEL_NOT_FOUND`; marker model ids `mock-embed-3072` ⇒ dimension mismatch, `mock-embed-nan` ⇒ non-finite ⇒ `PROVIDER_ERROR`).
**Ingest result** (`/v1/ingest` final NDJSON `result`) gains `embedding_dimension` (the verified vector length actually stored).

## 2. Backend API (`modules/ai/connection.ts`, routes under `/api/ai`, auth + same-origin guard, rate limited)
* `GET /api/ai/connection` →
```ts
{ connection: {
    configured: boolean;                                   // key + chat + embedding all set
    provider: "openrouter" | "openai" | "groq" | "gemini" | "mock" | null; providerLabel: string | null;
    apiKey: { configured: boolean; masked: string | null; status: "UNTESTED"|"VALID"|"INVALID"|"ERROR"|null };   // masked "••••abcd"
    chatModelId: string | null; embeddingModelId: string | null;
    embeddingDimension: number | null; /* + embeddingRequestDimensions, dimensionLimits, defaultEmbeddingDimension, reindex — see EMBEDDING_SETTINGS_SPEC §6 */ validatedAt: string | null;
    documents: { ready: number; stale: number; processing: number };   // stale = READY with a different embedding identity
    costNote: string } }                                      // "Saving makes two tiny paid requests (one chat, one embedding) with your key."
```
  No ciphertext/iv/tag/full key ever; response is built from explicit selects.
* `PUT /api/ai/connection` body (strict) `{ apiKey?: string; chatModelId: string; embeddingModelId: string }` — `chatModelId`/`embeddingModelId`: trimmed, 1–200 chars, regex `^[A-Za-z0-9][A-Za-z0-9._:/@+-]*$` (existing model-id rule); `apiKey`: optional; **omitted or blank ⇒ keep the saved key** (if there is none ⇒ `VALIDATION` field error); present ⇒ trimmed, printable ASCII, 8–512 chars (existing `apiKeySchema`). Flow: rate limit (5/min/user) → resolve key + provider (derive from a new key; reuse the saved credential's provider otherwise) → `rag.validateConfig(...)` → if any check failed: **422 `AI_CONFIG_INVALID`** `{ details: { checks, provider, fields: { apiKey?|chatModelId?|embeddingModelId?: message } } }`, nothing written, previous config intact; if rag_agent is unreachable ⇒ `UPSTREAM_UNAVAILABLE`/`PROVIDER_ERROR` envelope, nothing written. On success **one transaction**: upsert the encrypted credential for the provider (when a new key was supplied; `status=VALID`, `lastTestedAt=now`), upsert `ModelPreference` rows `DEFAULT` (chat) and `EMBEDDING` (embedding; `embeddingDimension` = measured, `validatedAt = now`), both pointing at that credential; task-specific rows (CHAT/MCQ/CQ/ANALYSIS) are **left untouched** (their feature-specific rules keep working; with none set, MCQ/CQ/analysis/chat all reuse the DEFAULT chat model via the existing `resolveModel` fallback). Response `200 { connection, checks, reembedRequired: boolean, documentsAffected: number }` (`reembedRequired` when the embedding identity changed and READY documents with the old identity exist). Audit `ai.connection_saved` (provider + whether the key/models changed; never any key material). No other component is allowed to read a half-saved state (the transaction is the only writer; readers see old or new).
* `POST /api/documents/reembed` → `{ queued, skipped }`: for the caller's documents with status READY/FAILED/NEEDS_OCR-excluded whose embedding identity differs from the current configuration, enqueue the existing reprocess path (idempotent via the job dedupe key, bounded to 200 per call, rate limited). Each document keeps its id, owner, name and permissions; new chunks are written under a new `processingVersion` and the document switches versions atomically only when the new set is complete (rag_agent contract §3), so an interrupted re-embed leaves the previous chunks in place.
* Existing `/api/ai/credentials*`, `/api/ai/preferences`, `/api/ai/providers` remain (API compatibility, per-run model override in generators, tests) but are no longer used by the settings UI.
* Document view gains `embeddingDimension: number|null` and `embeddingStale: boolean`.

## 3. Embedding compatibility rules (single helper `modules/ai/embedding-identity.ts`, used everywhere)
`identity(doc) = { provider: doc.embeddingProvider, model: doc.embeddingModel, dimension: doc.embeddingDimension ?? 1536 }` (`1536` applies only to rows written before the dimension was recorded — the old column was `vector(1536)`; the dimension is otherwise whatever was measured and may be any size 8–4096); `current = { provider, model, dimension: pref.embeddingDimension ?? 1536 }` from the user's EMBEDDING preference. **compatible(doc) ⇔ doc.status = READY ∧ identities equal.** Used by: chat preparation (`conversations/chat.ts`), generation (`questions/generation.ts`), assistant topic summaries, document listing (`embeddingStale`), the connection summary, and the re-embed endpoint. Document-only chat/generation with only stale documents ⇒ clear error "Your documents were indexed with a different embedding model. Open Documents → Re-embed" (existing wording improved); general mode skips stale documents with a warning. The query embedding always uses the user's current configuration, and rag_agent still verifies every vector's length (`EMBEDDING_DIMENSION_MISMATCH` ⇒ a clear error event, never a meaningless search). Ingest stores `embeddingProvider`, `embeddingModel`, `embeddingDimension` per document and `embeddingModel` per chunk (existing). The retrieval SQL's `embeddingModel` filter is unchanged.

## 4. Frontend (settings)
`/settings/providers` becomes **"AI connection"**: a single card/form with exactly three text inputs (API key as a password input with a show/hide *button*, chat model id, embedding model id) + **"Test and save"**; inline per-check results (auth / chat / embedding with ✓/✗ and the safe message), success toast, the read-only detected-provider line, the masked saved key / "Key configured" state, validated-at, measured dimension, the cost note, and — when `documents.stale > 0` — a banner with a **Re-embed N documents** button. Existing usage card and "automatic AI feedback" switch stay (non-text controls). `/settings/api-keys` redirects to `/settings/providers`; the "API keys" nav/search entries are removed. Per-task model pickers and generation-limit number inputs are removed from settings (defaults apply; API unchanged). No provider selector, base-URL field or dimension field. The Documents page shows a "Needs re-embedding" badge on stale documents and a bulk **Re-embed** action. All new strings are in the English/Bangla catalogs.

## 6. Optional live check (not run in CI; may incur provider charges)
Needs a real OpenRouter key. **Through the app:** start the stack, open *Settings → AI connection*, paste the key, copy a chat model id and an embedding model id from openrouter.ai/models (the embedding model must return 1536-dimensional vectors, e.g. `openai/text-embedding-3-small`), press *Test and save* (this makes one tiny chat request and one tiny embedding request), then upload a small document and ask a question. **Directly against rag_agent** (the same checks, nothing stored):
```bash
curl -s http://127.0.0.1:8100/v1/providers/validate \
  -H "authorization: Bearer $RAG_AGENT_TOKEN" -H 'content-type: application/json' \
  -d '{"provider":"openrouter","api_key":"'"$OPENROUTER_API_KEY"'","chat_model":"<chat-model-id>","embedding_model":"openai/text-embedding-3-small"}'
```
The response lists `auth` / `chat` / `embedding` results and the measured embedding dimension. As of 2026-10-24, OpenRouter's public model list does not expose a structured embedding-dimension field, which is why the dimension is **measured** with a real call rather than read from metadata.

## 7. Re-indexing workflow (what happens when the embedding model changes)
1. Saving a configuration whose embedding identity (provider + model + dimension) differs from the one the documents were indexed with is allowed once validated; the response says `reembedRequired` and how many documents are affected.
2. Those documents become **stale**: they are excluded from retrieval and generation with an explicit message (never searched with a mismatched vector space), and shown with a "Needs re-embedding" badge.
3. *Re-embed* queues the normal ingestion job per document (idempotent, owner-scoped, ≤ 200 per call). rag_agent writes the new chunks under a new `processingVersion` and switches the document to it atomically only when the whole set is stored; document id, owner, name and permissions never change.
4. Until a document has been re-embedded its previous chunks stay in the database (switching back to the old embedding model makes them searchable again). A failed re-embed marks that document FAILED (retry available) — documents are not partially indexed.

## 8. Increment 1 — generation settings, six checks, explicit testing, suggestions (implemented)
* **Schema (additive, nullable):** `ModelPreference.extraParams Json?` = `{ frequencyPenalty?, presencePenalty?, seed? }`; migration `20261025090000_model_extra_params`. Temperature, top-p and max tokens keep their columns. Settings live on the `DEFAULT` (chat) row, which MCQ/CQ/analysis/chat already fall back to. Reads are defensive: a stored value that fails the allow-list/range check is treated as "not set".
* **Ranges (server-enforced, strict object, unknown keys rejected):** temperature 0–2, top-p 0–1, max tokens 1–32768 (integer), frequency/presence penalty −2–2, seed 0–2³¹−1 (integer). `null` clears a parameter; an omitted `params` keeps the saved ones. A parameter that is `null` is **never sent** (`toWireParams`); the per-feature output caps (generation, analysis) still apply on top.
* **`PUT /api/ai/connection`** accepts `params`; **`POST /api/ai/connection/test`** takes the same body, runs the same checks and **writes nothing** (rate limit 8/min; saving 5/min). Nothing calls a provider unless one of these is invoked.
* **Six checks** (`checks.auth | chat | chatParams | embedding | dimension | database`, each `{ ok, skipped?, code?, message?, latency_ms?, dimension?, verified?, unsupported?, diagnostics? }`): key → chat model → chat parameters (metadata, then one tiny `require_parameters` request; skipped when no parameter is set) → embedding model available → measured size equals the configured size (`EMBEDDING_DIMENSION_MISMATCH`, never padded/truncated) → database can store it (`DB_VECTOR_UNAVAILABLE`, `DB_DIMENSION_MISMATCH`; read from `pg_extension` / `pg_attribute`). Saving requires all six to pass (a skipped `chatParams` is fine); otherwise `422 AI_CONFIG_INVALID` with `details.checks`, `details.fields` (`apiKey | chatModelId | embeddingModelId | params`) and nothing is written, so the last working settings stay active.
* **Diagnostics:** failed checks carry sanitised `diagnostics` (endpoint, HTTP status, short upstream code/provider) and are logged as `ai.connection.check_failed` (backend) and `validate_check_failed` (rag_agent) with no body/key/prompt. rag_agent answering 404/422/500 to the validate call is reported as `UPSTREAM_UNAVAILABLE` with `details.providerCode = "AI_SERVICE_OUTDATED"` ("restart rag_agent") instead of a provider error.
* **`GET /api/ai/public-models?kind=&provider=&q=&free=&exact=`** — optional suggestions from the provider's public list (keyless, cached by rag_agent, ≤ 40 rows). `exact=<id>` returns that model's listed `supported_parameters` so the form can warn; `null` means the list does not say. Manual entry is never restricted.
* **Not in this increment:** configurable embedding dimension and the vector-column change (Increment 2), retrieval settings (Increment 3).
